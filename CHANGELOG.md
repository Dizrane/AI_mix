# Changelog

Русский журнал изменений. Release-workflow берёт отсюда раздел публикуемой версии и вставляет его в заметки релиза как «Что нового»; если раздела для версии нет, в заметки попадает автоматический список коммитов. Перед выпуском новой версии добавьте сюда её раздел.

## v0.2.8 — 2026-08-13

### Роутинг классифицирован: настоящие Output, Input и Sends

- Кнопки роутинга больше не сдаются с «slot kind unclassified»: на реальном AX-дампе микшера с эталонным сендом найдены структурные признаки, различающие слоты. Занятый send — это вообще не кнопка, а группа с чекбоксом bypass и ручкой уровня (такой формы нет ни у одного другого элемента стрипа); кнопка выхода стоит сразу после слота Group; кнопка входа (шина aux или «Input N») — сразу после кнопки режима канала. Пакет теперь публикует честные факты «Output: Bus 1», «Input: Bus 2» и секцию Sends только с доказанными сендами — у каждого факта в source записано, каким именно признаком он доказан. Схема пакета 2.7.
- Честность не ослаблена: классификация требует и документированного соседа, и подписи-направления, поэтому «mastering assistant» после кнопки режима канала на Stereo Out фактом входа не становится, а кнопка-направление вне опознанных позиций по-прежнему публикуется как unclassified с requires_probe и запретом читать её как send. Уровень и панорама сенда не читаются (ручка отдаёт безразмерное число, панорамы в AX нет вовсе) и остаются requires_probe.
- Экран Analysis показывает итог классификации: сколько выходов, входов и сендов доказано и сколько кнопок осталось неопознанными.

## v0.2.7 — 2026-08-13

### Обновление прямо из приложения

- Приложение обновляет само себя: при запуске оно тихо сверяет свою версию с последним релизом на GitHub, и если вышла новая — в сайдбаре появляется кнопка «Update to vX». По нажатию скачивается релизный ZIP, новый `AI Mix Assistant.app` проверяется (версия внутри бандла обязана совпасть с релизом, исполняемый файл — существовать) и подменяет старый прямо в той же папке-оболочке; `Data/` со всеми анализами не затрагивается, приложение перезапускается уже новой версией. Скачивать репозиторий и переносить папку заново больше не нужно.
- Всё честно и вручную: автоматическая проверка только читает публичный API релизов и молчит без сети; установка происходит только по явному нажатию; любая ошибка до подмены оставляет текущую установку нетронутой, ошибка во время подмены откатывает старый `.app` обратно. В Settings появилась секция Updates с ручной проверкой («Check for Updates» / «Install»). Из транслоцированной read-only копии обновление честно отказывается работать и отправляет сначала нажать «Fix and Relaunch».

### Роутинг: ложные сенды устранены

- Анализатор публиковал как send-факты кнопки роутинга, которые Logic по Accessibility никак не помечает: кнопка выхода трека «Bus 1» превращалась в «send на Bus 1», а входная шина aux-канала — в его собственный «сенд». В реальном проекте без единого сенда пакет описывал восемь. Теперь такие кнопки публикуются тем, чем они являются, — «routing button» с известным направлением («Bus 1», «St Out») и слотом requires_probe: send это, выход трека или вход aux, без целевого зонда отличить нельзя, и документ прямо запрещает модели читать их как сенды. Схема пакета 2.6.
- Кнопки «St Out» / «Stereo Out» / «Output …» больше не теряются молча: под прежний шаблон «Bus …» они не подходили, и трек с выходом на Stereo Out выглядел как трек вообще без роутинга.
- Экран Analysis показывает «Routing buttons: N unclassified (send / output / aux input)» вместо ложного счётчика сендов.

## v0.2.6 — 2026-08-13

### AI-пакет: последняя полировка честности

- Сводка технических дефектов теперь стоит в начале раздела Audio Assets: файлы с цифровым клиппингом, true peak выше полной шкалы или заметным DC-смещением названы одной строкой каждый — модели не нужно выкапывать их из десяти блоков метрик. Если дефектов нет, сводка прямо это говорит. Полные числа по-прежнему у каждого ассета.
- «Bit depth: 32 · Format: PCM» читалось двусмысленно: формат теперь говорит, какой это PCM — `PCM (float)` или `PCM (integer)`, прямо из флагов файла.
- Описание валидации Mix Plan уточнено: диапазоны проверяются у параметров плагинов, а не у всех значений подряд — раньше текст обещал больше, чем делает проверка. Схема пакета 2.5.

## v0.2.5 — 2026-08-13

### AI-пакет: замкнут цикл «анализ → план → валидация»

- В документ добавлена точная схема Mix Plan — тот самый JSON, который приложение проверяет на экране Review: обязательные поля, шесть реализованных действий, таргетинг через `logicalTrackID`, пример с двумя действиями. Раньше формат нигде не описывался, модель придумывала свою структуру, и вставка её плана в Review заканчивалась «Invalid MixPlan JSON». Пример из документа прогоняется тестом через настоящий декодер приложения — расхождение сломает сборку.
- Первый ответ модели больше не обязан быть JSON-блобом: стадии анализа, интерпретации, проблем и вопросов читает человек, а не программа, поэтому они пишутся обычным Markdown (разделы ANALYSIS / INTERPRETATION / ISSUES / QUESTIONS). Строгий JSON остался только там, где его реально разбирает приложение — в финальном Mix Plan. Прежняя «схема ответа v2.0» с пустыми полями удалена вместе с путаницей версий.
- Документ компактнее без потери фактов: известные булевы флаги трека (Mute/Solo/Record/Monitoring/Selected/EQ) слиты в одну строку `Flags:` на блок, провенанс указывает число регионов вместо повторного перечисления их ID (полный список остался под каждым ассетом), а строка готовности из шапки убрана — ниже есть целый раздел готовности. Схема пакета 2.4.

## v0.2.3 — 2026-08-13

### Исправлен крэш

- Кнопка «Launch Logic Pro» больше не завершает приложение. Запуск другого приложения выполнялся через колбэк `NSWorkspace.openApplication`, а его AppKit вызывает на своей очереди LaunchServices: колбэк, написанный внутри main-actor-класса, считается привязанным к главному потоку, и проверка Swift 6 убивала процесс в момент вызова — ровно по нажатию кнопки. Теперь используется async-версия, которая возвращает результат уже на главном актёре, а неудачный запуск честно пишется в лог вместо тишины. Той же ошибкой был поражён «Fix and Relaunch» в сообщении про App Translocation — исправлено там же.
- Показ папок в Finder («Open Package Folder», «Open Audio Folder», Reveal Data) выполнялся из фонового исполнителя хранилища; теперь он тоже уходит на главный актёр.

### AI-пакет честен относительно того, что реально получила модель

- Документ больше не описывает три возможных режима доставки, а прямо заявляет тот, для которого сгенерирован: «Copy for AI» отдаёт только Markdown — и текст это утверждает, не отправляет модель искать `logic_snapshot.json` и WAV, не требует «прослушать все файлы» и прямо запрещает делать вид, что слушал; измеренные DSP-метрики названы той аудио-доказательной базой, которая в этом режиме действительно есть. Save Package по-прежнему выдаёт полный вариант с прослушиванием. Схема пакета 2.3.
- `Transport: known: 0` больше не публикуется: кнопки play/stop отдают «0»/«1», это не состояние транспорта, поэтому факт остаётся `unknown`.
- Раздел метров переименован в «Logic on-screen meters (AX)» и объясняет, что это показания экранных метров Logic (их Accessibility не отдаёт), а измеренные LUFS/пики лежат у каждого файла в Audio metrics — раньше «LUFS: unavailable» рядом с реальными числами читалось как «данных о громкости нет».
- Числа читаются как измерения: доли меньше 10 % сохраняют десятую (было «0% silent» прямо над списком диапазонов тишины), пик чуть ниже полной шкалы больше не печатается как «-0.0 dBTP», у каждой спектральной полосы указан Hz.
- Документ компактнее на ~15 % без потери фактов: регионы перечисляются одной строкой на трек с именами вместо блока на регион, пиксельные координаты таймлайна не публикуются как «время» (они зависят от зума и остаются в `audio_manifest.json`), а раздел провенанса — по одной строке на WAV вместо четырёх.

## v0.2.2 — 2026-08-13

### Локальный DSP-анализ экспортированных WAV

- Приложение теперь само считает объективные метрики по каждому экспортированному WAV — только системными средствами (AVFoundation + Accelerate/vDSP), только чтение, вне главного потока: integrated loudness по ITU-R BS.1770-4 (K-взвешивание, блоки 400 мс с перекрытием 75 %, гейты −70 LUFS и −10 LU), true peak по BS.1770-4 (4× оверсэмплинг полифазным FIR), sample peak и RMS всего файла, crest factor, доли энергии по шести фиксированным полосам спектра и спектральный центроид, стерео-метрики для 2-канальных файлов (корреляция L/R, соотношение mid/side), карта тишины (окна 100 мс ниже −60 dBFS, слитые в диапазоны секунд, плюс доля тишины) и технические флаги (DC-offset, счётчик сэмплов на цифровом клиппинге). Подробности методики — в `Documentation/AUDIO_METRICS.md`.
- Метрики — факты о конкретном WAV-файле, не о проекте Logic, и без музыкальных суждений: каждое значение несёт состояние; посчитано по реальному файлу → `known` с путём файла как источником; значения, которых не существует (стереокорреляция моно-файла, dB-уровень цифровой тишины), — честный `unavailable`.
- Метрики считаются только для ассетов со статусом `exported` и только от финальных подтверждённых файлов (никогда от промежуточных, которые Logic ещё дописывает), попадают в `audio_manifest.json` (схема манифеста 1.1) и в AI-пакет: у каждого экспортированного ассета появился подраздел «Audio metrics (computed locally, facts)», а инструкция для внешней LLM требует использовать метрики как первичную доказательную базу и явно заявлять конфликт собственного «слуха» с цифрами. Схема пакета поднята до 2.2.
- Результаты кэшируются по идентичности файла (путь + размер + дата модификации): Refresh Export Status не пересчитывает неизменившиеся файлы, а переэкспортированный файл честно анализируется заново.

### Название проекта вернулось в факты

- После честной проверки подписей (v0.2.1) имя проекта переставало определяться вообще: ни один контрол Logic не подписан «project», поэтому поиск по подписи мог дать только ложное совпадение. Теперь имя берётся из главного окна: сначала документ окна (`AXDocument` — путь к `.logicx`, из него имя файла), иначе заголовок окна как есть; в самом факте указано, из какого атрибута он прочитан. Если проект не открыт, имя по-прежнему `unavailable`. Имя проекта снова видно на экране Analysis и попадает в название папки и ZIP-архива AI-пакета (вместо `AI_Mix_Analysis_project.zip`).
- Подпись контрола больше не может стать собственным значением факта: Logic подписывает поле одним элементом, а значение показывает в другом, поэтому элемент без `AXValue` пропускается и берётся следующий с тем же названием. Раньше это давало факты вида «Key signature: known: Key Signature».

### Мелочи

- `manifest.json` в AI-пакете объявляет ту же версию схемы, что и сам документ пакета (была зафиксирована `2.0`).
- Множественные числа («1 WAV file missing», «1 action») доведены до конца — в интерфейсе, а не только в Markdown-пакете.

## v0.2.1 — 2026-08-13

### Честность фактов

- Метаданные проекта больше не «узнаются» по случайным подстрокам: метка должна совпадать с настоящей подписью контрола (title/description равен метке или начинается с неё как целое слово). Раньше «play» находилось внутри «Display», а «key» — внутри «keyboard», и чужое значение публиковалось как `known`-факт (например `Transport: known: Beats & Project`). Теперь без уверенного совпадения — честный `unavailable`.
- Инспектор главного окна Logic больше не порождает фантомные дубли channel strip'ов: настоящим Mixer'ом считается область с наибольшим числом стрипов, а зеркала выделенного трека из инспектора отбрасываются. Стрипы, которые есть только в инспекторе (например выход), сохраняются как реальные объекты; одноимённые стрипы внутри самого Mixer'а по-прежнему не сливаются (`ambiguous`).

### AI-пакет

- В основную инструкцию добавлены «режимы доставки»: полный пакет (ZIP/папка с WAV) — полный workflow с прослушиванием; только этот Markdown — модель прямо говорит, что файлов у неё нет, просит ZIP пакета и работает только по фактам, никогда не делая вид, что слушала аудио; платформа без поддержки аудио — заявляет ограничение и продолжает по фактам, задавая вопросы. Схема пакета поднята до 2.1.
- Полировка вывода: длительности и прочие числа округляются до 2 знаков («135.85 s» вместо «135.85066666666665 s»), «1 header(s)» заменено нормальным множественным числом, всегда-`unavailable` поля трека сжаты в одну строку «Unavailable: …» — факты `known` и `requires_probe` остаются отдельными строками.

## v0.2.0 — 2026-08-13

### Установка стала проще

- Приложение теперь само лечит App Translocation. Если macOS запустил его из карантинной read-only копии и хранилище данных недоступно, прямо в этом сообщении появляется кнопка **Fix and Relaunch**: она снимает карантин только с папки программы и перезапускает её из настоящего места. Папку можно держать где угодно — включая рабочий стол.

### Удобство

- Статус подключения обновляется сам: запустили Logic Pro или выдали разрешение Accessibility — экран Connection оживает без кнопки Refresh.
- Диалог подтверждения экспорта теперь честно описывает автоматический процесс (раньше он описывал старый ручной сценарий с ⌘⇧G и вставкой пути).
- Буфер обмена больше не затирается: автоматика экспорта сохраняет и восстанавливает то, что вы скопировали.
- После сканирования и запуска экспорта приложение возвращает себя на передний план, а не оставляет вас в Logic.
- Определение экспортированных WAV больше не обрывается через 2 минуты: ожидание продолжается, пока файлы появляются (до 10 минут), и завершается после минуты без изменений — большие проекты успевают.
- Если меню Logic не на английском, ошибка теперь прямо объясняет, что Logic Pro нужно переключить на английский интерфейс, и подсказывает как.
- В сайдбаре видна версия приложения.
