# Changelog

Русский журнал изменений. Release-workflow берёт отсюда раздел публикуемой версии и вставляет его в заметки релиза как «Что нового»; если раздела для версии нет, в заметки попадает автоматический список коммитов. Перед выпуском новой версии добавьте сюда её раздел.

## v0.2.28 — 2026-08-15

### Сенды: уровень как факт на доказанной шкале, set_send_level в валидаторе и LIVE (схема 2.28)

- Уровень send публикуется фактом только на шкале, которую доказала сама ручка — никогда не угадан. Два вида доказательства по силе: `AXValueDescription` ручки, отображающий число в dB (то же свидетельство одного момента, что и level-текст фейдера), — шкала dB; иначе числовой `AXValue`, ограниченный собственными `AXMinValue…AXMaxValue` ручки, — сырая шкала (позиция ручки — честный факт, явно безразмерный и никогда не выдаваемый за децибелы). Ручка, не доказавшая ни того, ни другого (реальный дамп Logic показывает именно её: безразмерный AXValue без границ), оставляет уровень `requires_probe` — как раньше. `SendFacts` несёт `levelScale` (dB/raw) и `levelRange` (доказанные границы; сырые границы не продаются как dB-диапазон: dB-диапазон публикуется только когда сам AXValue стоит на шкале dB в допуске 0.05).
- `set_send_level` в валидаторе: адресация через `target.sendDestination` (факт Destination дословно; два send'а в одну шину — отказ как неоднозначность, отсутствующий — `requires_probe`), исполняемо только для send'а с known-уровнем; значение, `parameters.current` и `parameters.delta` — на доказанной шкале send'а, диапазон — доказанные границы ручки, direction proof current/delta — та же арифметика и сверка с фактом, что у volume/pan (допуск 0.05). Пока шкала не доказана — `set_send_level` остаётся `unsupported`, ровно как весь action до появления фактов. `set_send_pan` всегда `unsupported`: Logic не экспонирует контрол панорамы send'а над AX вовсе, доказать шкалу невозможно — панорама send'а остаётся в MANUAL STEPS.
- LIVE-адаптер по контракту фазы 2: send находится тем же структурным свидетельством, что публикует факт (группа с подписью-назначением и чекбоксом bypass; слайдер «send knob» сразу за ней — иначе отказ), запись — на доказанной вживую шкале. С dB-описанием — общий с фейдером калиброванный путь (идемпотентное доказательство read → set(то же) → read, детекция шкалы по свидетельству одного момента, прямая запись на dB-шкале или измеренное серво по сырой, успех только когда описание ручки перечитывает цель в 0.05, откат при любом сбое); без dB — запись на шкале самих фактов (границы ручки), staleness-гейт против `parameters.current`, идемпотентное доказательство, верификация перечитыванием и откат. Очередь, halt-семантика и свежий скан после LIVE — без изменений; дифф после прогона теперь видит изменения уровней send (по содержимому, не по AX-путям — сдвиг путей при перескане не объявляется изменением).
- Замкнутый цикл покрывает сенды: `PlanVerifier` сверяет цель применённого `set_send_level` с перечитанным фактом уровня (send переопознаётся по Destination — id встраивают AX-пути и легально смещаются); отсутствующий, неоднозначный или недоказанный send — честный `unverifiable`, никогда не угадан.
- Пакет (схема 2.28): уровень send — строка факта с именованной шкалой и доказанным диапазоном; новая таблица «Send levels» — источник `parameters.current` для `set_send_level` (трек, назначение, уровень, шкала, диапазон); правила схемы и предпоставочный чеклист учат адресацию, шкалу и запреты (`set_send_pan` не бывает в плане); тексты LIVE в обеих доставках, Review-экране и README называют пять верифицированных действий. Тесты: доказательство шкалы без ложных known, все ветки валидатора, golden-path 4→5 с send-действием из собственной таблицы пакета, дифф и верификатор по сендам; `EXECUTOR.md`/`COMMAND_SCHEMA.md` соответствуют коду.

## v0.2.27 — 2026-08-15

### Замкнутый цикл «до/после»: верификация применённого плана и пост-apply AI-пакет (схема 2.27)

- Цикл замыкается после применения плана: автоматически после LIVE-очереди и по кнопке «Verify Applied Plan (Fresh Scan)» на экране Review — для планов, применённых руками. Свежий read-only скан диффует треки против снапшота, с которым план валидировался, и проверяет каждое valid-действие: абсолютная цель плана против перечитанного known-факта (`PlanVerifier`, допуск 0.05 — тот же, что у валидатора). Три честных исхода: `matched`, `mismatched` (показаны оба значения), `unverifiable` — не-known свежий факт называется своим состоянием и никогда не угадывается в результат; ни одна проверка не может породить ложный known.
- Метрики «до/после»: в момент верификации замораживается baseline измерений текущих файлов (движение фейдера меняет аудио только после нового экспорта/bounce, так что файлы на диске в этот момент — состояние, о котором рассуждал план). Кнопки пере-экспорта и пере-bounce доступны прямо на карточке верификации; `MetricsComparison` соединяет baseline с новыми измерениями по идентичности (кэш метрик по идентичности файла): строки существуют только там, где обе стороны реально измерены, LUFS/true peak/клиппинг показываются как «до → после (Δ)», а неизменённый файл помечается «unchanged file» и не выдаётся за звуковой эффект плана.
- Свежий снапшот УСВАИВАЕТСЯ как текущий анализ (raw + normalized сохраняются, ассеты пересобираются), поэтому следующий сгенерированный AI-пакет — пост-применённый второй круг: схема 2.27, `Post-apply snapshot: yes` в шапке и секция `Post-apply verification` с построчной сверкой целей, диффом треков и метриками до/после; пакет прямо велит модели оценить достигнутое и строить следующий план только от свежих фактов (`parameters.current` — только из свежей таблицы Current control values). Пакет без верифицированного цикла явно говорит `Post-apply snapshot: no`.
- Тесты: сверка целей в допуске/вне допуска, честные `unverifiable` (requires_probe, отсутствующий трек, ручные действия), соединение метрик по идентичности без сфабрикованных строк, пост-apply маркеры в обеих доставках; golden-path тест 4→5 не разошёлся. `EXECUTOR.md` описывает цикл; бамп схемы в тестах.

## v0.2.26 — 2026-08-15

### LIVE-исполнение четырёх фейдерных действий: проверенные адаптеры вместо честного отказа (схема 2.26)

- Появился первый живой адаптер записи: `set_volume`, `set_pan`, `set_mute`, `set_solo` теперь реально исполняются в Logic — через протокол `LiveActionAdapter` (locate по живым AX-свидетельствам, доказательство механизма записи до первой настоящей записи, перечитывание после каждой, `before`/`after` только из перечитанных значений). `SafeExecutor` маршрутизирует в адаптер только команды со статусом `valid` и только в режиме LIVE; действие без адаптера (плагины, сенды, роутинг) отказывает честно, как раньше, ничего не трогая.
- Полоса ищется по захваченному AX-пути и принимается только если элемент всё ещё несёт точную подпись трека и слайдер volume fader; иначе — поиск по живому Mixer тем же структурным свидетельством, что у нормализатора (зеркала инспектора исключены), и принимается только УНИКАЛЬНОЕ совпадение имени — два одноимённых strip'а отклоняются как неоднозначные.
- Перед записью volume/pan живое показание контрола сверяется с `parameters.current` из плана (допуск 0.05): проект, изменившийся после анализа, получает отказ «пересканируй и провалидируй заново» вместо исполнения дельт, о которых никто не рассуждал.
- Mute/solo — документированный AXPress по собственному контролу полосы с точной подписью и верой только перечитанному значению; контрол уже в целевом состоянии не нажимается. Volume — обязательная калибровка шкалы: реальный дамп Logic показывает сырые единицы на фейдере (AXValue 173 при 0.0 dB на level-тексте), поэтому шкала доказывается свидетельством одного момента (`FaderScale.detect`: AXValue == отображаемые dB в допуске 0.05 — шкала dB, иначе raw), механизм записи доказывается идемпотентной процедурой read → set(то же значение) → read (и AXValue, и отображаемые dB обязаны не сдвинуться), а по raw-шкале никакая кривая не угадывается — `FaderServoMath` ведёт фейдер измеренными секущими шагами в границах AXMinValue…AXMaxValue, и успех — только когда сама полоса показывает целевые dB в допуске 0.05. Любой сбой (нет границ, дисплей не отвечает, стагнация, исчерпан бюджет шагов) откатывает фейдер в исходное положение и называет причину. Pan пишется на шкале самих фактов (валидаторный диапазон −64…+63 читается с этого же слайдера), тоже с идемпотентным доказательством, верификацией и откатом.
- Очередь строго последовательная: провал исполнения останавливает всё после себя — остальные действия получают `not_executed` с именем провалившегося. После LIVE-очереди — свежий read-only fullScan и `DiffEngine.compare` (теперь видит и mute/solo) рядом с результатами по каждому действию.
- Безопасность: LIVE включается только явным выбором режима на экране Review плюс подтверждение на каждый запуск; DRY RUN остаётся дефолтом и ничего не пишет; ни одно действие не исполняется без `status == .valid` от валидатора. `EXECUTOR.md` и README переписаны под реальность («LIVE currently fails safely» больше не вся правда — описано, что именно верифицировано); пакет (схема 2.26) честно объясняет модели, как план используется теперь: DRY RUN по умолчанию, LIVE по явному выбору для четырёх действий, остальное — руками по MANUAL STEPS. Тесты: маршрутизация и halt-семантика очереди, детекция шкалы, сходимость и отказы серво-калибровки, диффы mute/solo, golden-path пакета не разошёлся с валидатором.

### Плагинные факты: производитель, параметры из открытых окон (схема 2.25)

- До сих пор у каждой линейки в пакете стояло «Plugins: unavailable», а `set_plugin_bypass` / `set_plugin_parameter` навсегда валидировались как `requires_probe` — ветка валидатора была мертва. Захват имени загруженного слота существовал (кнопка "audio plug-in" с непустой подписью), теперь он дополнен до полезных фактов, не нарушая дисциплину доказательств.
- Производитель — перекрёстная ссылка, не AX-факт: `known` только когда каталог установленных плагинов (`PluginInventory`) содержит ровно один плагин с точно таким именем; источник факта называет идентификатор AU. Общее или отсутствующее имя честно остаётся `unavailable`.
- Параметры читаются только из ОТКРЫТОГО окна плагина, сопоставленного слоту по уникальному именному свидетельству: заголовок окна должен назвать ровно один захваченный слот (при нескольких линейках с тем же плагином — ещё и ровно одно из имён их треков). Внутри окна параметр — это контрол с значением (slider/incrementor/combo/text field), чья собственная подпись — имя параметра, а `AXValue` парсится числом; диапазон публикуется только когда контрол экспонирует и `AXMinValue`, и `AXMaxValue`. Неоднозначное окно не даёт ничего. Сырой скан теперь захватывает `AXValueDescription` / `AXMinValue` / `AXMaxValue` дословно (старые снапшоты декодируются без изменений).
- Bypass слота остаётся `requires_probe`: AX не экспонирует состояние bypass на кнопке слота, а ложный `known` — худший из багов.
- Пакет: устаревший абзац «текущие цепочки плагинов НЕ предоставлены и НЕ анализируются» заменён честным — цепочки публикуются как захваченные факты под Plugins каждой линейки, «Plugins: unavailable» означает отсутствие захваченной цепочки. Схема 2.25. Тесты закрепляют: уникальное сопоставление производителя, привязку параметров окна к единственному слоту, отказ неоднозначного окна, рендер фактов в пакете и прохождение `set_plugin_parameter` через валидатор против тех же фактов.

### AI-пакет: правило приоритета при смешанной доставке (схема 2.24)

- Живой прогон выявил непредусмотренный сценарий: пользователь вставил текст «Copy for AI» И приложил ZIP «Save Package» в одном сообщении. Каждый документ честно утверждал свой режим, поэтому вставленный текст («аудио не доставлено, открывать нечего») приказывал модели игнорировать реально приложенные WAV, а его обязательная декларация требовала бы ложного «аудио не доставлено». Теперь обе преамбулы несут одно правило MIXED DELIVERY: каждый вариант остаётся самодостаточным по отдельности, а при совместной доставке приоритет у FULL PACKAGE-документа внутри ZIP — он единственный соответствует тому, что модель реально получила. Markdown-вариант прямо говорит: если ZIP всё же пришёл вместе с текстом, аудио ДОСТАВЛЕНО и действуют правила `AI_MIX_ANALYSIS.md` из ZIP, включая отмену запрета заявлять прослушивание; full-package-вариант зеркально объявляет притязания текстового варианта недействительными. Оба текста фиксируют, что варианты различаются только преамбулой доставки, а факты в них идентичны.
- Контракт закреплён тестом: обе доставки содержат правило MIXED DELIVERY с формулировкой приоритета, и full-package-вариант называет текстовый, не воспроизводя его строку доставки дословно.

## v0.2.23 — 2026-08-15

### AI-пакет: три слабости живого прогона закрыты (схема 2.23)

- Язык `reason`: правило «весь JSON — по-английски» получило явное исключение в обеих точках, где документ учит формату (абзац про язык ответа и пункт схемы про `reason`) — `reason` единственное человекочитаемое поле внутри JSON, экран Review показывает его пользователю под каждым действием, поэтому оно пишется на языке пользователя; ключи, имена действий, id, идентификаторы треков и числовые значения сверяются машинно и остаются ровно как в фактах. Валидатор не менялся — он по-прежнему проверяет только непустоту. `COMMAND_SCHEMA.md` описывает исключение.
- Обязательная декларация аудио-режима: в живом тесте модель без слуха написала «проверил все 10 WAV» и не сказала, что слушать не может. Теперь требование структурное в ОБЕИХ доставках: первый абзац секции ANALYSIS обязан открываться одной явной строкой — либо «прослушал WAV-файлы», либо «слушать не могу, работаю по измерениям и фактам»; формулировки вида «проверил файлы» декларацией не считаются. В markdown-only доставке строка обязана констатировать работу по измерениям (аудио не поставлялось) — вариант «прослушал» там даже не предлагается, чтобы не приглашать фабрикацию. Требование продублировано в пункте workflow про ANALYSIS с честным текстом для каждой доставки.
- Пример Mix Plan строится из реального снапшота: статический пример таргетил `track_2` — id, которого в проекте пользователя обычно нет, а модели копируют примеры, и скопированный placeholder давал `requires_probe`. Теперь пример берёт первый трек с known Volume И known Pan (те же факты, что таблица Current control values), подставляет его настоящий `logicalTrackID` и настоящие current-значения в оба действия с точной арифметикой delta и целями внутри диапазонов (у края диапазона направление хода переворачивается); числа рендерятся тем же форматтером, что и таблица, так что `current` совпадает с ней дословно. Снапшот без такого трека честно откатывается к прежнему статическому примеру. Тексты `reason` в примере остаются обучающими шаблонами и прямо названы таковыми. Тест закрепляет: сгенерированный пример целиком проходит декодер и валидатор приложения против того же снапшота без ретаргета.

### AI-пакет: протокол двух ответов и финальный чек-лист самопроверки (схема 2.22)

- Протокол двух ответов зафиксирован явно: первый ответ модели — только стадии 1–4 (ANALYSIS / INTERPRETATION / ISSUES / QUESTIONS) и НИ ОДНОГО JSON-блока `MIX PLAN` — план в первом ответе, даже как «черновик», обходит подтверждение пользователя и назван нарушением workflow. После подтверждения (этап 5) модель отдаёт только этап 6 — `MIX PLAN` + `MANUAL STEPS` — без повторения анализа; ответы пользователя на QUESTIONS имеют приоритет над предложенными дефолтами, а ответ, снимающий необходимость действия, убирает само действие. Раньше «не прыгай сразу в план» было сказано, но границы ответов модели додумывали по-разному.
- «Pre-delivery checklist (stage 6)» — девять проверяемых строк сразу после JSON-примера, последнее, что модель читает перед ответом: ровно один fenced-json-блок без прозы и висячих запятых; `version`/`status`/все поля примера/уникальные `id`; `target.trackID` существует в документе; значения в реальных диапазонах контролов (громкость с точностью 0.1 dB, пан целым числом); `current` скопирован из таблицы, `delta` = value − current и знак delta совпадает с направлением в `reason`; `value` — позиция контрола, никогда не LUFS/RMS/пик; `reason` — одно самодостаточное предложение; ни `set_solo` без запроса, ни действий, добавляющих плагины; каждый ISSUE прослеживаем; каждый шаг MANUAL STEPS называет трек, операцию и доказательство. Каждая строка зеркалит конкретное правило валидатора этапа 5 — провал строки означает отклонение действия на Review.
- `Documentation/LLM_PROMPT.md` догнал реальность: вместо давно неактуального «модель возвращает strict MixPlan JSON или request_probe» документ описывает действующий контракт — пакет как самодостаточную инструкцию, human-in-the-loop в два ответа и валидируемый этап 6; `LLMProvider` остаётся провайдер-нейтральным протоколом на будущее, транспорт по-прежнему не требуется.

Итог всегда один: баунс пишет ровно один несжатый PCM-файл — измерительный эталон микса, без лишних lossy-файлов рядом.
- Сделанное записывается фактами: в манифест (схема 1.6, обратная совместимость чтения сохранена) и AI-пакет (схема 2.14) добавляются строки «the app checked “Uncompressed” … and verified the check» и «the app unchecked “MP3” … so exactly one PCM mix file was written», лог называет каждое нажатие прямо. Вес у нажатий разный, по тому, что каждое защищает: не удавшаяся галочка PCM отменяет баунс (без неё PCM-файла не будет вовсе) — диалог закрывается, сообщение объясняет, что именно не получилось, с инструкцией отметить PCM вручную; сжатая галочка, которая не снялась, лишь выписала бы лишний файл рядом с WAV (детекция микса его игнорирует), поэтому она честно остаётся видимой в записанной таблице и называется в логе, но работающий баунс не отменяет.

Теперь завершённость Audio требует и валидированный файл баунса в `mix/`: галочка в сайдбаре, замок следующего этапа и кнопка «Continue to AI Package» открываются только после обоих шагов, а подпись карточки Mix (Stereo Out) говорит об этом прямо.

Нечитаемая таблица не блокирует ничего и публикуется как unavailable — как у Normalize.

Несохранённый проект по-прежнему опознаётся по заголовку своего собственного стандартного окна, даже когда поверх открыт диалог.

### Баунс микса (Stereo Out) — опорная точка для модели

Отсутствие баунса пакет называет ограничением прямо: выводы об итоговом миксе без него не подкреплены измерениями — и модели предписано это признавать, а не экстраполировать из треков.

- Автоматизация экспорта раньше оставляла формат, битность и Normalize «как в диалоге» не глядя: с Normalize = On (или Overload Protection Only при перегрузе) Logic переписывает громкость каждого экспортированного WAV — и вся доказательная база об относительных уровнях треков тихо становилась ложной, о чём ни пользователь, ни модель не узнавали. Теперь перед нажатием Export приложение читает подписанные контролы самого диалога (Format, Bit Depth, Normalize): любое значение Normalize, кроме Off, отменяет экспорт (диалог закрывается Escape, ничего не экспортировано) с честным объяснением — один раз поставить Off и экспортировать снова. Настройки по-прежнему только читаются, никогда не переключаются.
- Прочитанные настройки записываются фактами: в `audio_manifest.json` и AUDIO_ASSETS.md (схема манифеста 1.2) и в AI-пакет (схема 2.10) — «Export dialog Normalize: known: Off» с источником-контролом. Известное значение всегда Off (иначе экспорт не состоялся бы), и пакет прямо говорит, что WAV несут настоящие относительные уровни проекта. Нечитаемый контрол честно остаётся unavailable с предостережением; экспорт, который приложение не запускало (ручной, или после перезапуска приложения), публикуется как ненаблюдавшийся — безопасность уровней не выдумывается задним числом.

## v0.2.12 — 2026-08-14

### Папка программы переименовывается вместе с версией

- Релизный ZIP распаковывается в папку `AI_Mix_<версия>`, но обновление внутри приложения подменяло только `.app` — программа новой версии продолжала жить в папке со старым номером. Теперь после успешной подмены бандла папка-оболочка переименовывается в `AI_Mix_v<новая версия>`, и приложение перезапускается уже из неё; `Data/` со всеми анализами едет вместе с папкой, потому что переименовывается папка целиком. Переименовываются только имена релизной схемы (`AI_Mix_<версия>`, включая дрейфнувший формат без `v` — он приводится к каноническому); папку, названную пользователем по-своему, обновление не трогает никогда.

Всё безопасно: занятое соседней папкой имя, отсутствие прав на запись или неудавшийся перезапуск честно откатывают или пропускают переименование — оно никогда не ломает работающую установку и не проваливает уже завершённое обновление.

### Надёжность обновления и экспорта

- Установить обновление больше нельзя посреди работы: пока идёт анализ проекта или Logic экспортирует дорожки, кнопки Install/Update неактивны, а попытка установки честно объясняет причину. Подмена бандла с переименованием папки и перезапуском убила бы идущий скан или детекцию экспортированных файлов, а Logic продолжил бы писать WAV в путь со старым именем папки.
- Клавиши автоматизации экспорта (⌘⇧G, ⌘V, Return, Escape) теперь адресуются процессу Logic напрямую (postToPid), а не в общесистемный поток ввода: раньше, переключившись в другое приложение в момент автоматизации, можно было получить вставку пути назначения в чужое окно — например, в мессенджер.
- Буфер обмена вокруг экспорта сохраняется и восстанавливается целиком: каждый элемент со всеми его представлениями (файлы, картинки, форматированный текст), а не только простая строка, как раньше. Пустой буфер восстанавливается пустым — одолженный автоматизацией путь назначения больше не остаётся в буфере, если у пользователя ничего скопировано не было.

- Честность не ослаблена: классификация требует и документированного соседа, и подписи-направления, поэтому «mastering assistant» после кнопки режима канала на Stereo Out фактом входа не становится, а кнопка-направление вне опознанных позиций по-прежнему публикуется как unclassified с requires_probe и запретом читать её как send. Уровень и панорама сенда не читаются (ручка отдаёт безразмерное число, панорамы в AX нет вовсе) и остаются requires_probe.

## v0.2.3 — 2026-08-13

### Исправлен крэш

- Кнопка «Launch Logic Pro» больше не завершает приложение. Запуск другого приложения выполнялся через колбэк `NSWorkspace.openApplication`, а его AppKit вызывает на своей очереди LaunchServices: колбэк, написанный внутри main-actor-класса, считается привязанным к главному потоку, и проверка Swift 6 убивала процесс в момент вызова — ровно по нажатию кнопки. Теперь используется async-версия, которая возвращает результат уже на главном актёре, а неудачный запуск честно пишется в лог вместо тишины. Той же ошибкой был поражён «Fix and Relaunch» в сообщении про App Translocation — исправлено там же.
- Показ папок в Finder («Open Package Folder», «Open Audio Folder», Reveal Data) выполнялся из фонового исполнителя хранилища; теперь он тоже уходит на главный актёр.

### AI-пакет честен относительно того, что реально получила модель

- Документ больше не описывает три возможных режима доставки, а прямо заявляет тот, для которого сгенерирован: «Copy for AI» отдаёт только Markdown — и текст это утверждает, не отправляет модель искать `logic_snapshot.json` и WAV, не требует «прослушать все файлы» и прямо запрещает делать вид, что слушал; измеренные DSP-метрики названы той аудио-доказательной базой, которая в этом режиме действительно есть. Save Package по-прежнему выдаёт полный вариант с прослушиванием. Схема пакета 2.3.
- `Transport: known: 0` больше не публикуется: кнопки play/stop отдают «0»/«1», это не состояние транспорта, поэтому факт остаётся `unknown`.
- Раздел метров переименован в «Logic on-screen meters (AX)» и объясняет, что это показания экранных метров Logic (их Accessibility не отдаёт), а измеренные LUFS/пики лежат у каждого файла в Audio metrics — раньше «LUFS: unavailable» рядом с реальными числами читалось как «данных о громкости нет».
- Числа читаются как измерения: доли меньше 10 % сохраняют десятую (было «0% silent» прямо над списком диапазонов тишины), пик чуть ниже полной шкалы больше не печатается как «-0.0 dBTP», у каждой спектральной полосы указан Hz.
- Документ компактнее на ~15 % без потери фактов: регионы перечисляются одной строкой на трек с именами вместо блока на регион, пиксельные координаты таймлайна не публикуются как «время» (они зависят от зума и остаются в `audio_manifest.json`), а раздел провенанса — по одной строке на WAV вместо четырёх.

## v0.2.2 — 2026-08-13

### Локальный DSP-анализ экспортированных WAV

- Приложение теперь само считает объективные метрики по каждому экспортированному WAV — только системными средствами (AVFoundation + Accelerate/vDSP), только чтение, вне главного потока: integrated loudness по ITU-R BS.1770-4 (K-взвешивание, блоки 400 мс с перекрытием 75 %, гейты −70 LUFS и −10 LU), true peak по BS.1770-4 (4× оверсэмплинг полифазным FIR), sample peak и RMS всего файла, crest factor, доли энергии по шести фиксированным полосам спектра и спектральный центроид, стерео-метрики для 2-канальных файлов (корреляция L/R, соотношение mid/side), карта тишины (окна 100 мс ниже −60 dBFS, слитые в диапазоны секунд, плюс доля тишины) и технические флаги (DC-offset, счётчик сэмплов на цифровом клиппинге). Подробности методики — в `Documentation/AUDIO_METRICS.md`.
- Метрики — факты о конкретном WAV-файле, не о проекте Logic, и без музыкальных суждений: каждое значение несёт состояние; посчитано по реальному файлу → `known` с путём файла как источником; значения, которых не существует (стереокорреляция моно-файла, dB-уровень цифровой тишины), — честный `unavailable`.
- Метрики считаются только для ассетов со статусом `exported` и только от финальных подтверждённых файлов (никогда от промежуточных, которые Logic ещё дописывает), попадают в `audio_manifest.json` (схема манифеста 1.1) и в AI-пакет: у каждого экспортированного ассета появился подраздел «Audio metrics (computed locally, facts)», а инструкция для внешней LLM требует использовать метрики как первичную доказательную базу и явно заявлять конфликт собственного «слуха» с цифрами. Схема пакета поднята до 2.2.
- Результаты кэшируются по идентичности файла (путь + размер + дата модификации): Refresh Export Status не пересчитывает неизменившиеся файлы, а переэкспортированный файл честно анализируется заново.

### Название проекта вернулось в факты

- После честной проверки подписей (v0.2.1) имя проекта переставало определяться вообще: ни один контрол Logic не подписан «project», поэтому поиск по подписи мог дать только ложное совпадение. Теперь имя берётся из главного окна: сначала документ окна (`AXDocument` — путь к `.logicx`, из него имя файла), иначе заголовок окна как есть; в самом факте указано, из какого атрибута он прочитан. Если проект не открыт, имя по-прежнему `unavailable`. Имя проекта снова видно на экране Analysis и попадает в название папки и ZIP-архива AI-пакета (вместо `AI_Mix_Analysis_project.zip`).
- Подпись контрола больше не может стать собственным значением факта: Logic подписывает поле одним элементом, а значение показывает в другом, поэтому элемент без `AXValue` пропускается и берётся следующий с тем же названием. Раньше это давало факты вида «Key signature: known: Key Signature».

### Мелочи

- `manifest.json` в AI-пакете объявляет ту же версию схемы, что и сам документ пакета (была зафиксирована `2.0`).
- Множественные числа («1 WAV file missing», «1 action») доведены до конца — в интерфейсе, а не только в Markdown-пакете.
