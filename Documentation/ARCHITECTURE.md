# Architecture

`Accessibility` (read only) → `RawSnapshot` → `SnapshotNormalizer` → LLM (the Capy-API Assistant, or the user's own model via copy/paste) → `MixGraphDryCheck` → `MixEngine` offline render. Every AI Package delivery (schema 2.32) teaches the same deliverable — a MixGraph: the Assistant path extracts it from the thread transcript (`CapyAPIClient` carries the dialog; `Sources/Assistant.swift` orchestrates it), the manual paths accept it pasted on the Render stage, and rendering runs in a short-lived child process (`RenderChildProcess`), so a plugin crash can never take the app down.

The live-execution branch — LLM reply → `CommandValidator` → preview → `CommandExecutor` → fresh scan → `DiffEngine`, hosted by the Review stage — is preserved in code but hidden from the shipped UI: `WorkflowStage.visible` excludes `.review`, the sidebar and `go(to:)` use only visible stages, and no AI Package delivery teaches the `MixPlan` schema anymore. Its validator, executor, adapters and tests all remain in place and maintained, but nothing in the visible interface can validate a MixPlan or write to Logic Pro.

All concrete DAW work is behind protocols (`DAWAnalyzer`, `CommandExecutor`). Add a DAW by implementing those protocols. `SessionStore` persists exactly one current analysis under `Data/current`, next to the application bundle. That location is deliberate: the whole product lives in one self-contained folder, so deleting that folder (Settings → Delete AI Mix Assistant) removes the app and every trace of its data, and nothing is scattered into `~/Library`.

Logic Pro has no public, complete semantic automation API for these channel-strip operations. AX data is collected as evidence, not treated as a documented Logic model. A live adapter must be action-specific, use an allowed interaction mechanism, re-read the result, and be separately tested before registration. The first such adapter is `LogicChannelStripAdapter` (volume, pan, mute, solo — see `EXECUTOR.md`); `SafeExecutor` routes validator-approved actions to registered adapters in LIVE mode only, and every unadapted action keeps failing safely. With the Review stage hidden, this whole machinery is currently unreachable from the interface — it stays in the codebase as the proven foundation for a future live mode, not as shipped UI.
