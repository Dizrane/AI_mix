# LLM contract

No API transport ships in this application: the user hands the stage-4 AI Package to any external LLM themselves and pastes the answer back into the Review screen (stage 5). The package's own `AI_MIX_ANALYSIS.md` is the complete, self-contained instruction for the model — `AIPackageGenerator` embeds the workflow, the evidence rules and the machine-validated Mix Plan schema in the document itself, in two honest deliveries (full package with track WAVs plus the bounced Stereo Out mix, or the Markdown alone). The full-package instructions require the model to listen to the tracks and separately to the sum: overall balance, masking, stereo image and master-chain results are supported by the mix bounce, never inferred from isolated assets. Each delivery is self-sufficient, and both state the same MIXED DELIVERY rule for the case where the user hands over the pasted Markdown and the ZIP together: the full package is the delivery that matches reality, so its rules take priority over the text-only variant's delivery claims — the two variants differ only in their delivery preambles, never in facts.

The contract the document teaches: the model is the decision maker and works only from supplied facts (states other than `known` are not evidence and are never guessed). The workflow is human-in-the-loop in two strictly separated replies — the first delivers ANALYSIS / INTERPRETATION / ISSUES / QUESTIONS and no plan, opening ANALYSIS with one explicit line declaring the audio mode (listened to the WAVs, or working from the measurements because listening is impossible or the audio was not delivered); only after the user's confirmation does the second deliver `MIX PLAN` (exactly one JSON block conforming to the `MixPlan` schema, see `COMMAND_SCHEMA.md`) plus `MANUAL STEPS` for everything the schema cannot encode. Prose — including each action's `reason` inside the JSON — is written in the user's language; the rest of the JSON stays exactly as the facts state it. A pre-delivery checklist in the package mirrors the stage-5 validator and the human-only completeness rules. The embedded JSON example is built only from the snapshot's own known Volume/Pan facts (real `logicalTrackID`, current and delta); without such a fact it uses an empty action list instead of fabricating a target.

The `LLMProvider` protocol remains provider-neutral for a future in-app transport; none is configured or required today.
