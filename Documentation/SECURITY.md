# Security

Accessibility is sensitive. The app requests no permission automatically, opens System Settings only at user request, and treats scanning as read-only. Raw snapshots can contain project metadata and must stay on the local machine unless the user chooses to send the analysis to an LLM — by hand, or explicitly through the Assistant stage below.

Network discipline: the application talks to exactly two hosts, each for one purpose. The Capy API (`api.capy.ai`) carries the Assistant dialog — the base URL is a compile-time constant with a DEBUG-only override through the `CAPY_API_BASE_URL` environment variable, so a release build can reach nothing else on this path. The API key lives ONLY in the macOS Keychain (`CapyKeyStore`, one generic-password item), is loaded at call time, travels exclusively in the `Authorization` header of Capy requests, and never appears in `Data/`, logs, generated packages, saved transcripts or error messages; the Settings screen never pre-fills it back. There are no silent retries anywhere: thread polling backs off to a named interval ceiling and stops at a named total timeout, and every repeat — resume polling, re-verify, re-send — is the user's explicit click. Standing rules: network calls go to the Capy API only; a render (or any other write) never starts without the explicit button press; the existing GitHub Releases updater is the second, untouched host and keeps its own behaviour (user-visible checks, explicit install). Everything the Assistant produces is persisted honestly next to the analysis (package sent, full transcript, extracted graph) — never the key.

App Translocation: when Gatekeeper runs the downloaded app from a quarantined read-only copy, storage cannot initialize and the app offers "Fix and Relaunch". The repair runs only on explicit user request, removes the `com.apple.quarantine` attribute from the app's own shell folder only (resolved via `SecTranslocateCreateOriginalPathForURL`, never guessed), verifies the attribute is actually gone before claiming success, and relaunches the app from its real location. It never touches other files, never elevates privileges, and never weakens Gatekeeper beyond what Finder's own right-click → Open flow already approved for this app.

Closed shell: the folder around the `.app` is the program's entire footprint — all data lives in `Data/` beside the bundle, storage refuses to initialize when the `.app` sits directly in a shared folder (Downloads, Desktop, home…), and uninstalling deletes that one folder plus the few `~/Library` files macOS created for the app's exact bundle identifier. The only trace the app cannot remove is the Accessibility permission entry, which macOS owns.
