# Executor

Execution is sequential and result-oriented. `SafeExecutor` executes only commands the validator marked `valid`; DRY RUN (the default) never touches Logic; LIVE routes each command to the first registered `LiveActionAdapter` that declares `supports(action)`. An action with no adapter fails honestly — exactly the behaviour the executor had before any adapter existed. A failed action is critical: the rest of the queue is not executed, and every remaining command reports `not_executed` naming the action that halted it, because later moves may assume the earlier ones landed. After a LIVE queue the app runs a fresh read-only scan and shows `DiffEngine.compare` (changed / unchanged tracks) next to the per-action `ExecutionResult`s — the outcome the user sees is measured, never assumed.

The one shipped adapter is `LogicChannelStripLiveAdapter`, verified for `set_volume`, `set_pan`, `set_mute`, `set_solo` on Logic's Mixer channel strips. Its discipline:

- **Allowed mechanisms only.** AXValue writes and AXPress on the control the corresponding fact was read from. No screen coordinates, no AppleScript, no undocumented APIs.
- **Structural discovery, live.** The strip is found by the analyzer's documented rules applied to the live AX tree (the "mixer" AXLayoutArea with the most strips is the real Mixer; a strip is an AXLayoutItem holding a "volume fader" slider) and matched by its exact name — uniquely or not at all: an ambiguous name fails the action instead of guessing a target.
- **Staleness check.** For volume/pan the live readout must match the plan's `parameters.current` (tolerance 0.05); a project that changed since the analysis fails the action with instructions to rescan and re-validate.
- **Mandatory calibration before the first real write.** The fader's scale is never assumed: the adapter first performs an idempotent write (read → set(the same current value) → read) to prove the control accepts AXValue writes without changing state. The volume slider may use raw fader units rather than dB — `FaderCalibration.classify` compares the slider's own value with the strip's dB readout ("volume fader level"): equality proves a dB scale and the target is written directly; anything else is a raw scale, settled by `FaderCalibration.converge` — a closed-loop bisection over the slider's AXMinValue…AXMaxValue where every step's evidence is Logic's own dB readout after the write. Both functions are pure and tested. No formulaic dB↔raw mapping is trusted, because Logic documents none.
- **Readback or revert.** Every write counts only when the control's re-read confirms the target (tolerance 0.05, matching the 0.1 precision the user can set). A target the readback never confirms reverts the control to its previous value and fails the action with the exact reason — never "approximately".
- **Mute/solo** are AXPress on the strip's own 0/1 checkbox, verified by re-reading; a control already in the target state is reported executed without a press.

LIVE is enabled only by the user's explicit mode choice in the Review screen plus a confirmation dialog; DRY RUN remains the default. Adding an adapter for another action means implementing `LiveActionAdapter` with the same before/after readback and registering it on `SafeExecutor` — nothing executes through a guessed mechanism.
