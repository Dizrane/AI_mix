# Local audio metrics

`AudioMetricsAnalyzer` computes objective DSP measurements from each exported WAV, locally and read-only (AVFoundation for PCM reading, Accelerate/vDSP for the DSP — no third-party code, the file is never modified). The numbers are facts about the concrete audio file, not about the Logic project, and carry no musical interpretation: the app reports "integrated loudness −14.2 LUFS", never "too loud". Interpretation is the external LLM's job; the metrics give a model without audio capability a hard evidential base, and let a model with audio cross-check its hearing against measurements.

What is measured per exported WAV: integrated loudness per ITU-R BS.1770-4 (K-weighting re-derived for the file's actual sample rate — at 48 kHz the coefficients equal the published ones exactly — 400 ms blocks at 75 % overlap, −70 LUFS absolute and −10 LU relative gates); true peak per BS.1770-4 (4× oversampling through a polyphase FIR, max over channels, dBTP); sample peak and whole-file RMS (dBFS); crest factor (sample peak − RMS, dB); spectral energy shares over six fixed bands (sub 20–60 Hz, bass 60–250, low-mid 250–500, mid 500–2000, high-mid 2000–6000, high 6000–20000; Welch-averaged Hann 4096-point FFTs at 50 % overlap over a mono mixdown, shares relative to total spectral power) plus the spectral centroid (Hz); stereo facts for 2-channel files (L/R correlation coefficient, mid/side energy ratio in dB); a silence map (100 ms windows with RMS below −60 dBFS merged into second ranges, plus the silent share in percent — it complements region provenance, since the WAV is the full timeline including gaps); and technical flags (DC offset as the mean sample value, and the count of samples in runs of ≥ 3 consecutive samples at |x| ≥ 1 − 1e-4 — a number, not a verdict).

Every metric is a `Fact` with an explicit state. `known` means computed from the file's real samples, with the file path as source. `unavailable` is the honest answer where no finite value exists: stereo metrics of a mono file, and every dB/LUFS level of pure digital silence (−∞ has no finite dBFS value; the silence map carries the evidence instead). A false `known` is treated as the worst possible bug.

Metrics are attached only to assets with status `exported`, after the final file set is confirmed stable — never from mid-write intermediates — and land in `audio_manifest.json` and the AI package ("Audio metrics (computed locally, facts)" per asset). The bounced Stereo Out mix (`mix/`) is measured with the same analyzer once its file is stable and readable; its numbers are the reference for the sum, which no per-track WAV contains. Results are cached by file identity (absolute path + size + modification date), so Refresh Export Status recomputes nothing that did not change, while a re-exported file is honestly re-analyzed. All analysis runs off the main thread.
